## One-sentence description

Reef uses Muse to turn product websites, public GitHub repositories, and source documents into editable launch briefs and channel-specific social posts that founders review before sharing.

## Short description

Reef helps technical founders go from building a product to explaining it. Add a website, public GitHub repository, description, or source document. Muse creates an editable product brief, suggested claims with source references, and distinct drafts for X, Threads, and optionally LinkedIn. Review the preview, make it sound like you, and approve. Reef can then open the text in X or Threads’ compose window for you to post personally. Optional screenshots and uploaded launch media keep the assets together. The result is a focused launch workspace with human control at the moment of publication.

## Full project description

Technical founders can build a working product and still struggle to explain who it helps, why it matters, and what to say when launching it. The inputs already exist—a website, a README, a deck, screenshots—but translating them into a coherent campaign takes time and marketing experience.

Reef turns those inputs into a reviewable launch workflow. A founder adds a product website, public GitHub repository, description, or source files, then chooses a goal such as getting early users or collecting feedback. Muse synthesizes a product brief, suggests an audience, identifies product claims with source references, and writes distinct drafts for X and Threads, with optional LinkedIn content. The application validates the model’s output before saving it.

Founders can inspect the brief, review the suggested evidence, edit drafts, preview each post, and approve a specific version. Editing removes the previous approval. Approved posts can open in X or Threads with the text prefilled; the founder reviews the platform composer and presses Post. Screenshots and uploaded media can be downloaded and attached manually. An optional owner-scoped Buffer integration supports API-based queue submission, but it is not required for the direct-compose workflow.

Reef treats platform differences as product requirements. Hacker News is a human-written, manual submission task rather than another generated post. Samples cannot be approved for publishing, and unavailable analytics are shown as unavailable. A light, animated ASCII sky gives the workspace a distinctive visual identity without obscuring the work.

## Problem / inspiration

Building and launching require different kinds of work. A founder may know the code intimately but still struggle to translate features into a clear customer story. Generic copy generation starts too far from the product, while publishing tools assume the founder already knows what to say. Reef connects product context, channel-specific writing, review, and sharing in one small workflow.

## Target users

Independent developers, early-stage technical founders, and small software teams launching a working product or seeking early feedback. The first use case is turning existing product material into a small organic launch campaign.

## How we use Meta technology

Muse is the reasoning and writing layer of Reef. Our server calls Meta Model API’s Responses endpoint directly, using `muse-spark-1.3` by default, with a configurable model ID. The request combines founder input with extracted website text, public GitHub metadata and README content, and optional source attachments. Text sources are extracted; source images and PDFs are supplied as multimodal inputs.

Muse returns a structured product brief, audience suggestion, claims with source references, and channel-specific drafts with short explanations of their intended fit. Reef validates that response with Zod and persists the result in D1. Credentials remain server-side. Failed model calls produce visible errors rather than silently substituting sample output.

Separate launch-media uploads and demo-video links are organizational assets, not evidence that the current app transcribes or understands raw video. Screenshots are captured through an external screenshot service, not generated by Muse Image. Muse Code, Muse Image, SAM, fine-tuning, and MCP are not part of this implementation.

## What makes it different

Reef focuses on the transition from a built product to its first reviewable campaign. Three design choices support that focus:

1. Product context comes first: websites, README content, and documents inform the brief and drafts.
2. Review is part of the workflow: previews, suggested evidence, and version-specific approvals keep the founder in control.
3. Distribution respects the destination: X and Threads compose handoff is convenient, while Hacker News remains human-written and manual.

We are not claiming to have invented AI marketing or to have proven better conversion rates than existing tools. Our hypothesis is that this focused workflow reduces setup and editing effort for technical founders.

## Technical implementation / built with

- React 19 and TypeScript, using a Next-compatible Vinext application.
- Meta Model API / Muse Spark for campaign synthesis and writing.
- Cloudflare Workers runtime, D1 database, and R2 file storage.
- Zod response validation and Drizzle-managed SQL migrations.
- GitHub API/README ingestion for public repositories.
- Microlink for best-effort website screenshot capture.
- X and Threads web compose links; optional Buffer GraphQL publishing path.
- ASCII sky rendering, with the ASCII Sharks library retained and attributed.

Campaigns and uploads are scoped to authenticated users. Post approvals reference the draft version; changing the draft invalidates approval. The optional Buffer route claims a submission using a conditional database update before contacting the provider, preventing concurrent duplicate submission. Uncertain provider outcomes are held for reconciliation instead of blindly retried.

## Biggest challenge

The hard part was separating a useful draft from an authorized publishing action. Model output, saved campaign state, human edits, and external publishing can change independently. Reef uses explicit draft states, version-bound approval, and conditional database updates to keep those transitions understandable. Platform differences also shaped the design: a convenient X compose handoff is appropriate, while an automatically generated Hacker News submission is not.
