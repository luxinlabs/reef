# Reef — two-minute demo plan

This is a recording plan, not a claim that a video has been created. Follow the actual portal’s duration/format requirements if they differ.

## Before recording

- Open the current app with working authentication and MODEL_API_KEY configured server-side.
- Use a real product you are authorized to show, with a public website or GitHub README and a short accurate description.
- Run one live generation successfully and inspect the claims. Keep that campaign saved for a fallback walkthrough.
- If generation is slow, edit the waiting period in the recording and label the time cut. Do not pass fixture output off as a live model response.
- Include one image you may share. Raw launch video uploads are stored assets; do not imply that Muse has analyzed them.
- Log in to X or Threads if demonstrating compose handoff. Stop before clicking Post unless you separately intend to publish.
- Hide developer credentials, personal browser tabs, private media, and unrelated account details.
- Verify that the final video and app links are accessible to judges.

## Screen sequence and narration

| Time | Show | Suggested narration |
|---|---|---|
| 0:00–0:15 | Reef overview and its animated ASCII sky | “Building a product and explaining it are two different jobs. Reef helps technical founders turn what they built into a launch worth sharing.” |
| 0:15–0:35 | New launch: real product name, website or public GitHub repository, description, goal | “I start with material I already have: my product page, README, or source documents. I choose a goal, such as finding early users or getting feedback.” |
| 0:35–0:55 | Generate, then product brief and source-reference details | “Muse reads the supplied context and proposes a product brief, an audience, and claims with source references. These are suggestions to verify, not automatically trusted facts.” |
| 0:55–1:20 | Campaign cards for X and Threads; preview and edit | “Reef creates a different conversation for each channel. I can preview the exact text and edit anything that doesn’t sound like me. Each approval belongs to one version.” |
| 1:20–1:40 | Approve a real draft, then open the X or Threads composer | “Approving does not post anything. The approved text opens in the platform’s composer, where I review it and press Post myself. I don’t need a Buffer integration for this flow.” |
| 1:40–1:50 | Media gallery and Hacker News manual task | “Screenshots and launch assets stay with the campaign. Platforms with different rules get different workflows: Hacker News stays human-written and manual.” |
| 1:50–2:00 | Return to campaign / overview | “Reef brings product understanding, channel-specific writing, and a deliberate handoff together. The next step is connected publishing and measuring which messages actually bring users.” |

## Fallback if the live call fails

Show the visible error honestly. If using a campaign generated earlier with Muse, say “Here is a campaign generated earlier.” If using the built-in sample, say “This is the labeled sample workflow.” Do not say the sample proves live API integration. A video with successful actual Muse generation is substantially stronger.

## Screenshot capture list

1. Overview showing the latest sky-themed interface and product identity.
2. New launch with public GitHub input and optional source/media fields.
3. Product brief with an expanded source reference.
4. X/Threads campaign preview with the review controls visible.
5. Actual platform compose window with prepared text, before final posting.

Use screenshots from the running application. No fabricated analytics or mock “published” receipts.

## Optional 30-second pitch

“Reef helps technical founders turn a working product into a launch worth sharing. Give it a website, public GitHub repository, or source document. Muse turns that context into a product brief and distinct social drafts. You verify the claims, preview and edit the text, and approve a version before opening it in X or Threads to post. It’s a focused bridge from product context to a founder-controlled launch.”
